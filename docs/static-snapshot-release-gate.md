# 静态快照发布门禁

爬虫导出失败时保留旧数据，仍不足以保护应用发布：仓库里已经存在的空快照也会被复制到部署产物。因此应用发布前必须验证实际携带的数据。

从仓库根目录执行：

```text
python scripts/validate_static_snapshot.py --data-dir static/data
```

脚本只读文件，使用 Python 标准库，不导入 Flask、不连接数据库或其他服务，也不会生成数据、修改成功时间或清理文件。错误只显示文件或字段，不输出书籍内容。退出码 0 表示快照结构与非空条件通过；退出码 1 表示拒绝发布。

## 校验范围

- 明确的七个 `*_books.json` 分源文件及 `all_books.json`、`update_time.json`。不扫描翻译包或前端构建 manifest 等其他 JSON。
- 各来源必须是书籍列表，书名和作者必须为非空文本；允许某些来源为空，但全部来源总数必须大于零。
- 汇总必须覆盖相同来源，逐源内容与分源文件一致；元数据中的总数和来源集合必须与实际数据一致。缺文件不能视为空来源。
- 成功时间必须有可解析的历史凭据。旧版全局成功时间可以保留；部分成功可保留各来源旧成功时间。发布或尝试时间不能单独替代抓取成功时间，空来源的成功时间也不能替其他非空来源证明成功。
- 可选的 `sync_attempt.json` 可以记录失败或部分成功。最近一次失败不使已保留的有效旧快照自动失效，也不能推进其成功时间。

这个门禁不判断数据是否足够新鲜，也不证明每个来源成功。来源的新鲜度、全局成功与业务最终回执仍需独立验收。旧版没有来源成功时间的记录不会被补造为新鲜数据。

## 发布入口

Actions 的 deploy job 在任何 Render 部署请求前校验。HF 同步只携带这一校验脚本，并在替换 Space 克隆目录前再次验证实际暂存的静态数据。Docker 在复制源码后、完成镜像前校验。

`render.yaml` 的 native buildCommand 同样先校验，再安装依赖。已有 Render 服务不会因为修改仓库配置就必然采用新命令；必须在获准的发布准备中核对实际平台配置。当前平台若仍启用 On Commit 且保留旧构建命令，依然可能绕过 Actions 门禁，不能直接合并上线。

全空快照会有意阻止构建或发布。应先准备可追溯的有效非空快照及恢复副本，不能为通过门禁填演示书籍、伪造时间或删除校验。也不能用当前空 JSON 覆盖生产有效数据或充当回滚材料。

本门禁不改变发布授权：合并、部署、生产同步、数据库迁移、平台设置和权限调整仍按项目的独立确认流程执行。回滚使用事先验证的批准部署制品与有效快照，保留数据库版本历史和持久回执。

# 首页／排行榜中文书名补齐

## 现象与原因

2026-11-02 对 Render 主站、HF 镜像分别冻结全部 13 个分类的公开响应，各 155 条记录。两站相同的 28 本书缺少 `title_zh`，没有发现非空标题直接回显原英文的情况。

桌面和手机服务器返回页面均确认新书主标题仍显示英文。模板原本就优先使用 `title_zh`，缺失时回退英文；本次没有证据表明模板选错字段。

10 月 31 日的 PR #287 补齐了 16 条 `description_zh`，没有补齐相应的 `title_zh`；当时模板回归只检查简介和原文保留，遗漏了中文标题。当前另外 12 本缺少中文标题，其中 6 本公开简介原文也为空，但均有可翻译的英文书名。HF 不执行自动翻译，缺少静态译名会持续回退英文。初始主翻译服务未产出译文的原因仍没有生产错误日志证据。

## 本次修复

- 仅在现有语言包条目新增 28 个 `title_zh`，按 ISBN 精确匹配，不覆盖已有中文书名。
- 译名经上下文审校，作为本站参考译名，不宣称是正式中文出版名。人物、机构和系列名称按现有简介与原始详情理解；`LICORICE` 为猫名，沿用简介的“利科里斯”，`THE FAMILY CROSS` 的 Cross 按姓氏翻译。
- 所有原有语言包字段、英文原名、简介、详情、精确替换规则及元数据保持不变。没有编造缺失简介，也没有更换翻译供应商、添加依赖或清理生产数据库。
- 冻结 fixture `tests/fixtures/ranking-missing-titles-20261102.json` 保留原书名、原简介、ISBN、来源 URL 与响应 SHA256，以及经审校的参考译名。
- 新增 28 本 × 两种语言 × 两端模板的 112 项真实首页渲染回归，同时检查 API 序列化字段和英文原名保留。修复前先确认全部因缺少中文标题而失败，再补语言包。
- 补包后的回归发现“安迪的 Bravo 剪贴簿”被既有书名清洗规则截成“安迪的 Bravo”。原因是规则把空格后 1 至 4 个汉字当作署名，即使没有“译”标记也会删除。新增两个失败回归后，将该分支收紧为仅清理明确带“译”的署名，保留已有字段标签、书名号等清洗逻辑。

## 本地验收与发布边界

测试结果、精确提交及发布状态以本任务外部证据目录 `.debug/ranking-title-repair-20261102/` 的最终验收记录为准。文档写入时尚未宣称已部署；旧事件的 64 项浏览器通过结果不能作为本次书名验收。

浏览器工具本轮返回 `MCP tool call requires approval, but approval policy is never`，因此已取得的线上证据为公开 API 与服务器 HTML，并非执行客户端脚本后的浏览器验收。发布后应核对两站全部分类的标题、英文原名及中英文两端页面；若浏览器工具仍受限，必须如实保留该限制。

Render 运行时语言包相对 main 还有 17 条新增详情，已单独冻结在 `runtime-nontitle-differences-before.json`。本次不把这些未经本轮审校的详情混入书名补丁；原始响应保留，未清理其生产数据库来源。
